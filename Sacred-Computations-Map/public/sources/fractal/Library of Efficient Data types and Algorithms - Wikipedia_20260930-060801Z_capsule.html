# Library of Efficient Data types and Algorithms

- [日本語](https://ja.wikipedia.org/wiki/LEDA)
 [Edit links](https://www.wikidata.org/wiki/Special:EntityPage/Q6542691#sitelinks-wikipedia)                          From Wikipedia, the free encyclopedia   Software library

The **Library of Efficient Data Types and Algorithms** (**LEDA**) is a free [software library](https://en.wikipedia.org/wiki/Library_(computing)) providing [C++](https://en.wikipedia.org/wiki/C++) implementations of a broad variety of [algorithms](https://en.wikipedia.org/wiki/Algorithms) for [graph theory](https://en.wikipedia.org/wiki/Graph_theory) and [computational geometry](https://en.wikipedia.org/wiki/Computational_geometry).[[1]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:2-1) It was originally developed by the [Max Planck Institute for Informatics](https://en.wikipedia.org/wiki/Max_Planck_Institute_for_Informatics) [Saarbrücken](https://en.wikipedia.org/wiki/Saarbr%C3%BCcken).[[2]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-Stony_Brook_University_-_The_Stony_Brook_Algorithm_Repository_-_LEDA_-_A_Library_of_Efficient_Data_Types_and_Algorithms-2) From 2001 to 2023 LEDA was further developed and commercially distributed by the Algorithmic Solutions Software GmbH. Since 2024 a free version (LEDA-7) is available from [leda.uni-trier.de](https://leda.uni-trier.de/).

## Technical details

### Data types

[[edit](https://en.wikipedia.org/w/index.php?title=Library_of_Efficient_Data_types_and_Algorithms&action=edit&section=2)]

#### Numerical representations

[[edit](https://en.wikipedia.org/w/index.php?title=Library_of_Efficient_Data_types_and_Algorithms&action=edit&section=3)]

LEDA provides four additional numerical representations alongside those built-in to C++: `integer`, `rational`, `bigfloat`, and `real`:

- LEDA's `integer` type offers an improvement over the built-in `int` datatype by eliminating the problem of [overflow](https://en.wikipedia.org/wiki/Integer_overflow) at the cost of unbounded memory usage for increasingly large numbers.
- It follows that LEDA's `rational` type has the same resistance to overflow because it is based directly on the mathematical definition of [rational](https://en.wikipedia.org/wiki/Rational_number) as the quotient of two `integer`s.
- The `bigfloat` type improves on the C++ floating-point types by allowing for the [significand](https://en.wikipedia.org/wiki/Significand) (also commonly called mantissa) to be set to an arbitrary level of precision instead of following the [IEEE standard](https://en.wikipedia.org/wiki/IEEE_754).
- LEDA's `real` type allows for precise representations of [real numbers](https://en.wikipedia.org/wiki/Real_number), and can be used to compute the sign of a radical expression.[[1]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:2-1)

### Error checking

[[edit](https://en.wikipedia.org/w/index.php?title=Library_of_Efficient_Data_types_and_Algorithms&action=edit&section=4)]

LEDA makes use of [certifying algorithms](https://en.wikipedia.org/wiki/Certifying_algorithm) to demonstrate that the results of a function are mathematically correct. In addition to the input and output of a function, LEDA computes a third "witness" value which can be used as an input to checker programs to validate the output of the function. LEDA's checker programs were developed in Simpl, an [imperative programming language](https://en.wikipedia.org/wiki/Imperative_programming), and validated using [Isabelle/HOL](https://en.wikipedia.org/wiki/Isabelle/HOL), a software tool for checking the correctness of mathematical proofs.[[3]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:1-3)

The nature of a witness value often depends on the type of mathematical calculation being performed. For LEDA's planarity testing function, If the graph is [planar](https://en.wikipedia.org/wiki/Planar_graph), a combinatorial [embedding](https://en.wikipedia.org/wiki/Embedding) is produced as a witness. If not, a [Kuratowski subgraph](https://en.wikipedia.org/wiki/Kuratowski's_theorem) is returned. These values can then be passed directly to checker functions to confirm their validity. A developer only needs to understand the inner-workings of these checker functions to be confident that the result is correct, which greatly reduces the learning curve compared to gaining a full understanding of LEDA's planarity testing algorithm.[[4]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-4)

## Use cases

[[edit](https://en.wikipedia.org/w/index.php?title=Library_of_Efficient_Data_types_and_Algorithms&action=edit&section=5)]

LEDA is useful in the field of [computational geometry](https://en.wikipedia.org/wiki/Computational_geometry) due to its support for exact representations of [real numbers](https://en.wikipedia.org/wiki/Real_number) via the `leda_real` datatype. This provides an advantage in accuracy over [floating-point arithmetic](https://en.wikipedia.org/wiki/Floating-point_arithmetic). For example, calculations involving radicals are considerably more accurate when computed using `leda_real`. Algorithms such as [parametric search](https://en.wikipedia.org/wiki/Parametric_search), a technique for solving a subset of optimization problems, and others under the [real RAM](https://en.wikipedia.org/wiki/Real_RAM) model of computation rely upon real number parameters to produce accurate results.[[5]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:0-5)

## Alternatives

[[edit](https://en.wikipedia.org/w/index.php?title=Library_of_Efficient_Data_types_and_Algorithms&action=edit&section=6)]

[Boost](https://en.wikipedia.org/wiki/Boost_(C++_libraries)) and [LEMON](https://en.wikipedia.org/wiki/LEMON_(C++_library)) are potential alternative libraries with some benefits in efficiency due to different implementations of fundamental algorithms and data structures. However, neither employs a similar set of correctness checking, particularly when dealing with floating-point arithmetic. [CGAL](https://en.wikipedia.org/wiki/CGAL) is an alternative for geometric algorithms and also combines floating point, interval, and arbitrary precision arithmetic to achieve robustness.[[3]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:1-3)

Library of Efficient Data types and Algorithms

# Library of Efficient Data types and Algorithms

- [日本語](https://ja.wikipedia.org/wiki/LEDA)
 [Edit links](https://www.wikidata.org/wiki/Special:EntityPage/Q6542691#sitelinks-wikipedia)                          From Wikipedia, the free encyclopedia   Software library

The **Library of Efficient Data Types and Algorithms** (**LEDA**) is a free [software library](https://en.wikipedia.org/wiki/Library_(computing)) providing [C++](https://en.wikipedia.org/wiki/C++) implementations of a broad variety of [algorithms](https://en.wikipedia.org/wiki/Algorithms) for [graph theory](https://en.wikipedia.org/wiki/Graph_theory) and [computational geometry](https://en.wikipedia.org/wiki/Computational_geometry).[[1]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:2-1) It was originally developed by the [Max Planck Institute for Informatics](https://en.wikipedia.org/wiki/Max_Planck_Institute_for_Informatics) [Saarbrücken](https://en.wikipedia.org/wiki/Saarbr%C3%BCcken).[[2]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-Stony_Brook_University_-_The_Stony_Brook_Algorithm_Repository_-_LEDA_-_A_Library_of_Efficient_Data_Types_and_Algorithms-2) From 2001 to 2023 LEDA was further developed and commercially distributed by the Algorithmic Solutions Software GmbH. Since 2024 a free version (LEDA-7) is available from [leda.uni-trier.de](https://leda.uni-trier.de/).

#### Numerical representations

[[edit](https://en.wikipedia.org/w/index.php?title=Library_of_Efficient_Data_types_and_Algorithms&action=edit&section=3)]

LEDA provides four additional numerical representations alongside those built-in to C++: `integer`, `rational`, `bigfloat`, and `real`:

- LEDA's `integer` type offers an improvement over the built-in `int` datatype by eliminating the problem of [overflow](https://en.wikipedia.org/wiki/Integer_overflow) at the cost of unbounded memory usage for increasingly large numbers.
- It follows that LEDA's `rational` type has the same resistance to overflow because it is based directly on the mathematical definition of [rational](https://en.wikipedia.org/wiki/Rational_number) as the quotient of two `integer`s.
- The `bigfloat` type improves on the C++ floating-point types by allowing for the [significand](https://en.wikipedia.org/wiki/Significand) (also commonly called mantissa) to be set to an arbitrary level of precision instead of following the [IEEE standard](https://en.wikipedia.org/wiki/IEEE_754).
- LEDA's `real` type allows for precise representations of [real numbers](https://en.wikipedia.org/wiki/Real_number), and can be used to compute the sign of a radical expression.[[1]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:2-1)

Error checking

# Error checking

[[edit](https://en.wikipedia.org/w/index.php?title=Library_of_Efficient_Data_types_and_Algorithms&action=edit&section=4)]

LEDA makes use of [certifying algorithms](https://en.wikipedia.org/wiki/Certifying_algorithm) to demonstrate that the results of a function are mathematically correct. In addition to the input and output of a function, LEDA computes a third "witness" value which can be used as an input to checker programs to validate the output of the function. LEDA's checker programs were developed in Simpl, an [imperative programming language](https://en.wikipedia.org/wiki/Imperative_programming), and validated using [Isabelle/HOL](https://en.wikipedia.org/wiki/Isabelle/HOL), a software tool for checking the correctness of mathematical proofs.[[3]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:1-3)

The nature of a witness value often depends on the type of mathematical calculation being performed. For LEDA's planarity testing function, If the graph is [planar](https://en.wikipedia.org/wiki/Planar_graph), a combinatorial [embedding](https://en.wikipedia.org/wiki/Embedding) is produced as a witness. If not, a [Kuratowski subgraph](https://en.wikipedia.org/wiki/Kuratowski's_theorem) is returned. These values can then be passed directly to checker functions to confirm their validity. A developer only needs to understand the inner-workings of these checker functions to be confident that the result is correct, which greatly reduces the learning curve compared to gaining a full understanding of LEDA's planarity testing algorithm.[[4]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-4)

Use cases

# Use cases

[[edit](https://en.wikipedia.org/w/index.php?title=Library_of_Efficient_Data_types_and_Algorithms&action=edit&section=5)]

LEDA is useful in the field of [computational geometry](https://en.wikipedia.org/wiki/Computational_geometry) due to its support for exact representations of [real numbers](https://en.wikipedia.org/wiki/Real_number) via the `leda_real` datatype. This provides an advantage in accuracy over [floating-point arithmetic](https://en.wikipedia.org/wiki/Floating-point_arithmetic). For example, calculations involving radicals are considerably more accurate when computed using `leda_real`. Algorithms such as [parametric search](https://en.wikipedia.org/wiki/Parametric_search), a technique for solving a subset of optimization problems, and others under the [real RAM](https://en.wikipedia.org/wiki/Real_RAM) model of computation rely upon real number parameters to produce accurate results.[[5]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:0-5)

Alternatives

# Alternatives

[[edit](https://en.wikipedia.org/w/index.php?title=Library_of_Efficient_Data_types_and_Algorithms&action=edit&section=6)]

[Boost](https://en.wikipedia.org/wiki/Boost_(C++_libraries)) and [LEMON](https://en.wikipedia.org/wiki/LEMON_(C++_library)) are potential alternative libraries with some benefits in efficiency due to different implementations of fundamental algorithms and data structures. However, neither employs a similar set of correctness checking, particularly when dealing with floating-point arithmetic. [CGAL](https://en.wikipedia.org/wiki/CGAL) is an alternative for geometric algorithms and also combines floating point, interval, and arbitrary precision arithmetic to achieve robustness.[[3]](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms#cite_note-:1-3)
