A **Lagged Fibonacci generator** (**LFG** or sometimes **LFib**) is an example of a [pseudorandom number generator](https://en.wikipedia.org/wiki/Pseudorandom_number_generator). This class of [random number generator](https://en.wikipedia.org/wiki/Random_number_generator) is aimed at being an improvement on the 'standard' [linear congruential generator](https://en.wikipedia.org/wiki/Linear_congruential_generator). These are based on a generalisation of the [Fibonacci sequence](https://en.wikipedia.org/wiki/Fibonacci_sequence).

The Fibonacci sequence may be described by the [recurrence relation](https://en.wikipedia.org/wiki/Recurrence_relation):

      S  n   =  S  n − 1   +  S  n − 2     {\displaystyle S_{n}=S_{n-1}+S_{n-2}}

Hence, the new term is the sum of the last two terms in the sequence. This can be generalised to the sequence:

      S  n   ≡  S  n − j   ⋆  S  n − k     ( mod  m )  , 0 < j < k   {\displaystyle S_{n}\equiv S_{n-j}\star S_{n-k}{\pmod {m}},0<j<k}

In which case, the new term is some combination of any two previous terms. *m* is usually a power of 2 (*m* = 2*M*), often 232 or 264. The     ⋆   {\displaystyle \star }   operator denotes a general [binary operation](https://en.wikipedia.org/wiki/Binary_operation). This may be either addition, subtraction, multiplication, or the [bitwise](https://en.wikipedia.org/wiki/Bitwise_operation) exclusive-or operator ([XOR](https://en.wikipedia.org/wiki/XOR)). The theory of this type of generator is rather complex, and it may not be sufficient simply to choose random values for j and k. These generators also tend to be very sensitive to initialisation.

Generators of this type employ *k* words of state (they 'remember' the last *k* values).

If the operation used is addition, then the generator is described as an *Additive Lagged Fibonacci Generator* or ALFG, if multiplication is used, it is a *Multiplicative Lagged Fibonacci Generator* or MLFG, and if the XOR operation is used, it is called a *Two-tap [generalised feedback shift register](https://en.wikipedia.org/wiki/Generalised_feedback_shift_register)* or GFSR. The [Mersenne Twister](https://en.wikipedia.org/wiki/Mersenne_Twister) algorithm is a variation on a GFSR. The GFSR is also related to the [linear-feedback shift register](https://en.wikipedia.org/wiki/Linear-feedback_shift_register), or LFSR.

## Properties of lagged Fibonacci generators

[[edit](https://en.wikipedia.org/w/index.php?title=Lagged_Fibonacci_generator&action=edit&section=1)]

The maximum period of lagged Fibonacci generators depends on the binary operation     ⋆   {\displaystyle \star }  . If addition or subtraction is used, the maximum period is (2*k* − 1) × 2*M*−1 [*[citation needed](https://en.wikipedia.org/wiki/Wikipedia:Citation_needed)*]. If multiplication is used, the maximum period is (2*k* − 1) × 2*M*−3, or 1/4 of period of the additive case. If bitwise xor is used, the maximum period is 2*k* − 1.

For the generator to achieve this maximum period, the polynomial:

 *y* = *x**k* + *x**j* + 1

must be [primitive](https://en.wikipedia.org/wiki/Primitive_polynomial_(field_theory)) over the integers mod 2. Values of *j* and *k* satisfying this constraint have been published in the literature.

  Popular pairs of primitive polynomial degrees[[1]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-1)[[2]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-2)  *j*75246512863197353168334273418  *k*1017557115931631275215216076071279

Another list of possible values for *j* and *k* is on page 29 of volume 2 of *[The Art of Computer Programming](https://en.wikipedia.org/wiki/The_Art_of_Computer_Programming)*:

 (24, 55), (38, 89), (37, 100), (30, 127), (83, 258), (107, 378), (273, 607), (1029, 2281), (576, 3217), (4187, 9689), (7083, 19937), (9739, 23209)

Note that the smaller number have short periods (only a few "random" numbers are generated before the first "random" number is repeated and the sequence restarts).

If addition is used, it is required that at least one of the first *k* values chosen to initialise the generator be odd. If multiplication is used, instead, it is required that all the first *k* values be odd, and further that at least one of them is ±3 mod 8.[[3]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-3)

It has been suggested that good ratios between j and k are approximately the [golden ratio](https://en.wikipedia.org/wiki/Golden_ratio).[[4]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-uniform-4)

## Problems with LFGs

[[edit](https://en.wikipedia.org/w/index.php?title=Lagged_Fibonacci_generator&action=edit&section=2)]

In a paper on four-tap shift registers, [Robert M. Ziff](https://en.wikipedia.org/wiki/Robert_M._Ziff?action=edit&redlink=1), referring to LFGs that use the XOR operator, states that "It is now widely known that such generators, in particular with the two-tap rules such as R(103, 250), have serious deficiencies. [Marsaglia](https://en.wikipedia.org/wiki/George_Marsaglia) observed very poor behavior with R(24, 55) and smaller generators, and advised against using generators of this type altogether. ... The basic problem of two-tap generators R(a, b) is that they have a built-in three-point correlation between      x  n     {\displaystyle x_{n}}  ,      x  n − a     {\displaystyle x_{n-a}}  , and      x  n − b     {\displaystyle x_{n-b}}  , simply given by the generator itself ... While these correlations are spread over the size     p = m a x ( a , b , c , … )   {\displaystyle p=max(a,b,c,\ldots )}   of the generator itself, they can evidently still lead to significant errors.".[[5]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-5) This only refers to the standard LFG where each new number in the sequence depends on two previous numbers. A three-tap LFG has been shown to eliminate some statistical problems such as failing the [Birthday Spacings](https://en.wikipedia.org/wiki/Diehard_tests) and Generalized Triple tests.[[4]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-uniform-4)

## Example implementation

[[edit](https://en.wikipedia.org/w/index.php?title=Lagged_Fibonacci_generator&action=edit&section=3)]

A simple implementation in the [C](https://en.wikipedia.org/wiki/C_(programming_language)) programming language may look as shown below. This implementation uses 64-bit words and has a period of (2607 -1) × 263

```
#define R (607)
#define S (273)

#include <stdint.h>

uint64_t  X[R];

uint64_t  gen_rand()
{
    static int j = S - 1, k = R - 1;
	uint64_t  r;

    r = X[k] = X[k] + X[j--];
	k--;
	if (j < 0)
		j = R - 1;
	else if (k < 0)
		k = R - 1;
	return r;
}
```

## Usage

[[edit](https://en.wikipedia.org/w/index.php?title=Lagged_Fibonacci_generator&action=edit&section=4)]
- [Freeciv](https://en.wikipedia.org/wiki/Freeciv) uses a lagged Fibonacci generator with {j = 24, k = 55} for its random number generator.
- The [Boost library](https://en.wikipedia.org/wiki/Boost_library) includes an implementation of a lagged Fibonacci generator.
- [Subtract with carry](https://en.wikipedia.org/wiki/Subtract_with_carry), a lagged Fibonacci generator engine, is included in the [C++11](https://en.wikipedia.org/wiki/C++11) library.
- The [Oracle Database](https://en.wikipedia.org/wiki/Oracle_Database) implements this generator in its DBMS_RANDOM package (available in Oracle 8 and newer versions).

A **Lagged Fibonacci generator** (**LFG** or sometimes **LFib**) is an example of a [pseudorandom number generator](https://en.wikipedia.org/wiki/Pseudorandom_number_generator). This class of [random number generator](https://en.wikipedia.org/wiki/Random_number_generator) is aimed at being an improvement on the 'standard' [linear congruential generator](https://en.wikipedia.org/wiki/Linear_congruential_generator). These are based on a generalisation of the [Fibonacci sequence](https://en.wikipedia.org/wiki/Fibonacci_sequence).

The Fibonacci sequence may be described by the [recurrence relation](https://en.wikipedia.org/wiki/Recurrence_relation):

      S  n   =  S  n − 1   +  S  n − 2     {\displaystyle S_{n}=S_{n-1}+S_{n-2}}

Hence, the new term is the sum of the last two terms in the sequence. This can be generalised to the sequence:

      S  n   ≡  S  n − j   ⋆  S  n − k     ( mod  m )  , 0 < j < k   {\displaystyle S_{n}\equiv S_{n-j}\star S_{n-k}{\pmod {m}},0<j<k}

In which case, the new term is some combination of any two previous terms. *m* is usually a power of 2 (*m* = 2*M*), often 232 or 264. The     ⋆   {\displaystyle \star }   operator denotes a general [binary operation](https://en.wikipedia.org/wiki/Binary_operation). This may be either addition, subtraction, multiplication, or the [bitwise](https://en.wikipedia.org/wiki/Bitwise_operation) exclusive-or operator ([XOR](https://en.wikipedia.org/wiki/XOR)). The theory of this type of generator is rather complex, and it may not be sufficient simply to choose random values for j and k. These generators also tend to be very sensitive to initialisation.

Generators of this type employ *k* words of state (they 'remember' the last *k* values).

If the operation used is addition, then the generator is described as an *Additive Lagged Fibonacci Generator* or ALFG, if multiplication is used, it is a *Multiplicative Lagged Fibonacci Generator* or MLFG, and if the XOR operation is used, it is called a *Two-tap [generalised feedback shift register](https://en.wikipedia.org/wiki/Generalised_feedback_shift_register)* or GFSR. The [Mersenne Twister](https://en.wikipedia.org/wiki/Mersenne_Twister) algorithm is a variation on a GFSR. The GFSR is also related to the [linear-feedback shift register](https://en.wikipedia.org/wiki/Linear-feedback_shift_register), or LFSR.

Properties of lagged Fibonacci generators

# Properties of lagged Fibonacci generators

[[edit](https://en.wikipedia.org/w/index.php?title=Lagged_Fibonacci_generator&action=edit&section=1)]

The maximum period of lagged Fibonacci generators depends on the binary operation     ⋆   {\displaystyle \star }  . If addition or subtraction is used, the maximum period is (2*k* − 1) × 2*M*−1 [*[citation needed](https://en.wikipedia.org/wiki/Wikipedia:Citation_needed)*]. If multiplication is used, the maximum period is (2*k* − 1) × 2*M*−3, or 1/4 of period of the additive case. If bitwise xor is used, the maximum period is 2*k* − 1.

For the generator to achieve this maximum period, the polynomial:

 *y* = *x**k* + *x**j* + 1

must be [primitive](https://en.wikipedia.org/wiki/Primitive_polynomial_(field_theory)) over the integers mod 2. Values of *j* and *k* satisfying this constraint have been published in the literature.

  Popular pairs of primitive polynomial degrees[[1]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-1)[[2]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-2)  *j*75246512863197353168334273418  *k*1017557115931631275215216076071279

Another list of possible values for *j* and *k* is on page 29 of volume 2 of *[The Art of Computer Programming](https://en.wikipedia.org/wiki/The_Art_of_Computer_Programming)*:

 (24, 55), (38, 89), (37, 100), (30, 127), (83, 258), (107, 378), (273, 607), (1029, 2281), (576, 3217), (4187, 9689), (7083, 19937), (9739, 23209)

Note that the smaller number have short periods (only a few "random" numbers are generated before the first "random" number is repeated and the sequence restarts).

If addition is used, it is required that at least one of the first *k* values chosen to initialise the generator be odd. If multiplication is used, instead, it is required that all the first *k* values be odd, and further that at least one of them is ±3 mod 8.[[3]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-3)

It has been suggested that good ratios between j and k are approximately the [golden ratio](https://en.wikipedia.org/wiki/Golden_ratio).[[4]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-uniform-4)

Problems with LFGs

# Problems with LFGs

[[edit](https://en.wikipedia.org/w/index.php?title=Lagged_Fibonacci_generator&action=edit&section=2)]

In a paper on four-tap shift registers, [Robert M. Ziff](https://en.wikipedia.org/wiki/Robert_M._Ziff?action=edit&redlink=1), referring to LFGs that use the XOR operator, states that "It is now widely known that such generators, in particular with the two-tap rules such as R(103, 250), have serious deficiencies. [Marsaglia](https://en.wikipedia.org/wiki/George_Marsaglia) observed very poor behavior with R(24, 55) and smaller generators, and advised against using generators of this type altogether. ... The basic problem of two-tap generators R(a, b) is that they have a built-in three-point correlation between      x  n     {\displaystyle x_{n}}  ,      x  n − a     {\displaystyle x_{n-a}}  , and      x  n − b     {\displaystyle x_{n-b}}  , simply given by the generator itself ... While these correlations are spread over the size     p = m a x ( a , b , c , … )   {\displaystyle p=max(a,b,c,\ldots )}   of the generator itself, they can evidently still lead to significant errors.".[[5]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-5) This only refers to the standard LFG where each new number in the sequence depends on two previous numbers. A three-tap LFG has been shown to eliminate some statistical problems such as failing the [Birthday Spacings](https://en.wikipedia.org/wiki/Diehard_tests) and Generalized Triple tests.[[4]](https://en.wikipedia.org/wiki/Lagged_Fibonacci_generator#cite_note-uniform-4)

Example implementation

# Example implementation

[[edit](https://en.wikipedia.org/w/index.php?title=Lagged_Fibonacci_generator&action=edit&section=3)]

A simple implementation in the [C](https://en.wikipedia.org/wiki/C_(programming_language)) programming language may look as shown below. This implementation uses 64-bit words and has a period of (2607 -1) × 263

```
#define R (607)
#define S (273)

#include <stdint.h>

uint64_t  X[R];

uint64_t  gen_rand()
{
    static int j = S - 1, k = R - 1;
	uint64_t  r;

    r = X[k] = X[k] + X[j--];
	k--;
	if (j < 0)
		j = R - 1;
	else if (k < 0)
		k = R - 1;
	return r;
}
```

Usage

# Usage

[[edit](https://en.wikipedia.org/w/index.php?title=Lagged_Fibonacci_generator&action=edit&section=4)]
- [Freeciv](https://en.wikipedia.org/wiki/Freeciv) uses a lagged Fibonacci generator with {j = 24, k = 55} for its random number generator.
- The [Boost library](https://en.wikipedia.org/wiki/Boost_library) includes an implementation of a lagged Fibonacci generator.
- [Subtract with carry](https://en.wikipedia.org/wiki/Subtract_with_carry), a lagged Fibonacci generator engine, is included in the [C++11](https://en.wikipedia.org/wiki/C++11) library.
- The [Oracle Database](https://en.wikipedia.org/wiki/Oracle_Database) implements this generator in its DBMS_RANDOM package (available in Oracle 8 and newer versions).
